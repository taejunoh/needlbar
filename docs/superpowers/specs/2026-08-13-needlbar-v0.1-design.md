# Needlbar v0.1 Design

**Status:** Approved design baseline  
**Date:** 2026-08-13  
**Working name:** Needlbar  
**License target:** MIT  

## 1. Product Definition

Needlbar v0.1 is a lightweight, native macOS menu-bar monitor for Claude Code, Codex, and Cursor. It locally aggregates token usage and estimated cost through an embedded `tokscale-core` engine, independently retrieves provider subscription quota/reset information, and exposes the results through one overview menu-bar item plus optional provider-specific menu-bar modules.

### Goals

- Native macOS menu-bar experience using Swift, SwiftUI, and AppKit.
- Support Claude Code, Codex, and Cursor in v0.1.
- Show usage, estimated cost, quota utilization, and reset times.
- Keep usage history and parsing local-first.
- Require no Needlbar account and collect no telemetry.
- Reuse existing provider authentication whenever practical.
- Keep provider parsing separate from provider quota/authentication logic.
- Make the application installable as a single app without requiring a separate Tokscale installation.

### Non-goals for v0.1

- Windows or Linux support.
- Cloud sync or a hosted backend.
- Leaderboards, social features, or Needlbar accounts.
- GitHub integration, commit/PR attribution, or productivity scoring.
- Notifications and webhooks.
- Session/prompt content browsing.
- Supporting more than Claude Code, Codex, and Cursor.
- A generalized third-party provider plugin marketplace.

## 2. Product Surface

### 2.1 Hybrid menu-bar model

Needlbar uses a hybrid menu-bar structure inspired by modular system monitors.

Default installation:

- Overview module: enabled.
- Claude module: disabled.
- Codex module: disabled.
- Cursor module: disabled.

Users may enable any provider-specific module independently.

Each enabled menu-bar module can display one metric:

- quota remaining,
- tokens used today, or
- estimated cost today.

The Overview quota metric represents the most constrained eligible quota window across enabled providers: the window with the lowest remaining percentage.

### 2.2 Overview popover

The Overview popover shows:

- total tokens today,
- total estimated cost today,
- provider rows for Claude, Codex, and Cursor,
- each provider's headline quota remaining when available,
- a compact seven-day usage chart,
- stale/error indicators without discarding the last known good reading,
- access to Settings.

### 2.3 Provider popover

Each provider popover shows:

- today's total tokens,
- today's estimated cost,
- input tokens,
- output tokens,
- cache-read tokens,
- cache-write tokens when available,
- all supported quota windows,
- reset timestamps,
- data freshness state.

Models, sessions, projects, prompt text, and source content are intentionally omitted from v0.1 UI.

### 3.1 Ownership rules

#### `tokscale-core`

Owns:

- local session discovery,
- parsing,
- deduplication,
- aggregation,
- model pricing,
- cost estimation,
- normalized usage values.

Must not own Needlbar-specific quota or UI behavior.

#### `needlbar-source-sync`

Owns:

- provider-specific hydration required before `tokscale-core` can parse a usage source,
- Cursor usage-export synchronization and local cache freshness,
- bounded network access for usage-source hydration.

Must not calculate subscription quota and must not duplicate parsing/aggregation already owned by `tokscale-core`. Claude and Codex do not require a v0.1 source-sync adapter because their usage sources are local session stores.

#### `needlbar-quota`

Owns:

- provider quota retrieval,
- reset windows,
- authentication discovery and refresh,
- provider-specific quota parsing,
- provider-specific network/RPC fallbacks.

Must not parse token-history files already owned by `tokscale-core`.

#### `needlbar-bridge`

Owns:

- the Rust-to-Swift boundary,
- stable C-callable functions,
- JSON serialization,
- memory ownership/freeing,
- panic containment,
- schema versioning.

Must not contain presentation logic.

#### `NeedlbarCore`

Owns:

- decoding bridge payloads,
- merging independently refreshed usage and quota data,
- last-known-good state,
- freshness/staleness classification,
- refresh scheduling,
- module configuration,
- UI-free formatting helpers.

Must not re-parse provider logs or reinterpret raw provider auth formats.

#### `Needlbar`

Owns only presentation and native application lifecycle:

- `NSStatusItem` management,
- popover/window presentation,
- SwiftUI views,
- Settings UI,
- launch-at-login integration when later added,
- Sparkle integration when release infrastructure is enabled.

## 4. Provider Data Flows

### 4.1 Claude

Usage/cost:

```text
~/.claude/projects + ~/.claude/transcripts
                -> tokscale-core
                -> normalized usage
```

Quota:

```text
existing Claude credential/OAuth evidence
                -> Anthropic quota usage API
                -> ClaudeQuotaSnapshot
```

Fallback policy:

1. Use valid existing Claude OAuth/credential state.
2. Refresh if supported and required.
3. If valid local authentication cannot be resolved, mark quota as `requiresAuthentication`.
4. v0.1 does not automatically crawl unrelated browser profiles to obtain Claude cookies.

### 4.2 Codex

Usage/cost:

```text
~/.codex/sessions + archived sessions when available
                -> tokscale-core
                -> normalized usage
```

Quota:

```text
existing Codex auth/OAuth
        -> Codex/OpenAI quota API
        -> CLI RPC fallback when appropriate
        -> CodexQuotaSnapshot
```

Fallback policy:

1. Existing OAuth/auth state.
2. Provider API.
3. Codex CLI RPC when API credentials are unavailable or invalid and the CLI route is viable.
4. Otherwise `requiresAuthentication`.

### 4.3 Cursor

Usage/cost:

```text
Cursor account usage export
        -> needlbar-source-sync
        -> local tokscale-compatible cursor cache
        -> tokscale-core
        -> normalized usage
```

Quota:

```text
Cursor.app local auth/session
        -> Cursor web/API usage endpoint
        -> optional explicit browser-session import fallback
        -> CursorQuotaSnapshot
```

Cursor is intentionally not modeled as a local JSONL-only provider.

Browser-cookie access is not a silent first-choice path in Needlbar v0.1. If needed, it must be explicit in Settings and explain why the access is required.

## 5. Normalized Swift Data Model

```swift
struct ProviderSnapshot: Sendable {
    let provider: ProviderID
    let usage: UsageSnapshot?
    let quota: QuotaSnapshot?
    let usageStatus: DataStatus
    let quotaStatus: DataStatus
    let updatedAt: Date
}
```

```swift
struct UsageSnapshot: Sendable {
    let inputTokens: UInt64
    let outputTokens: UInt64
    let cacheReadTokens: UInt64
    let cacheWriteTokens: UInt64
    let totalTokens: UInt64
    let estimatedCostUSD: Decimal
    let today: UsagePeriod
    let last7Days: UsagePeriod
    let last30Days: UsagePeriod
}
```

```swift
struct QuotaSnapshot: Sendable {
    let windows: [QuotaWindow]
}

struct QuotaWindow: Sendable, Identifiable {
    let id: String
    let title: String
    let usedPercent: Double
    let resetsAt: Date?
}
```

```swift
enum DataStatus: Sendable {
    case fresh
    case stale(lastSuccessfulAt: Date)
    case unavailable
    case requiresAuthentication
    case error(message: String, lastSuccessfulAt: Date?)
}
```

### Data model rules

- Usage and quota may succeed or fail independently.
- A provider with valid usage but unavailable quota still renders usage normally.
- Quota windows are arrays; the model must not collapse providers to a single percentage.
- Percent values are normalized to `0...100` before crossing into Swift.
- Provider identity/authentication secrets never cross into Swift presentation models.

## 6. Rust/Swift ABI Contract

### 6.1 ABI style

The bridge exposes a deliberately small C ABI and transfers payloads as UTF-8 JSON strings.

Initial functions:

```c
const char *needlbar_usage_snapshot_json(void);
const char *needlbar_quota_snapshot_json(void);
const char *needlbar_diagnostics_json(void);
void needlbar_free_string(const char *ptr);
```

Exact signatures may be refined during the implementation plan, but v0.1 should avoid per-provider ABI functions unless measurement proves a single aggregate call is too expensive.

### 6.2 Envelope

All production bridge calls return one envelope schema:

```json
{
  "schemaVersion": "needlbar.v1",
  "ok": true,
  "generatedAt": "2026-08-13T15:00:00Z",
  "data": {},
  "errors": []
}
```

Failure:

```json
{
  "schemaVersion": "needlbar.v1",
  "ok": false,
  "generatedAt": "2026-08-13T15:00:00Z",
  "data": null,
  "errors": [
    {
      "provider": "claude",
      "code": "requiresAuthentication",
      "message": "Claude authentication was not available"
    }
  ]
}
```

### 6.3 ABI invariants

- Rust owns allocated output strings.
- Swift must always free successful non-null pointers with `needlbar_free_string`.
- Rust panics must not unwind across FFI.
- Unknown additive JSON fields must be ignored by Swift decoders.
- Breaking schema changes require a schema version bump.
- Usage and quota errors should be represented per provider whenever partial data remains usable.

## 7. Refresh and Caching

### 7.1 Usage refresh

Primary trigger:

- file-system changes affecting known local session sources,
- debounced by approximately one second.

Safety refresh:

- every five minutes.

Cursor source hydration is owned by `needlbar-source-sync`, not `tokscale-core` and not the quota layer. It uses a provider-specific bounded network cadence because its source is not a normal local append-only transcript. A five-minute freshness window is the v0.1 default; manual refresh bypasses the freshness gate.

### 7.2 Quota refresh

Default interval:

- every five minutes.

On popover open:

- if quota data is older than 60 seconds, request a background refresh without blocking display.

Manual refresh:

- available from the popover/settings.

### 7.3 Last-known-good behavior

A failed refresh must not replace a valid prior reading with empty data.

Each usage/quota stream stores:

- current successful snapshot,
- last successful refresh timestamp,
- latest failure information.

The UI shows stale state when appropriate while continuing to render the last successful values.

## 8. Privacy and Security

### 8.1 Local-first policy

Needlbar has no backend in v0.1.

Needlbar does not upload:

- token history,
- source code,
- prompts,
- assistant responses,
- file paths,
- account identifiers,
- provider credentials.

### 8.2 Content minimization

Needlbar should not intentionally parse or expose prompt/response text when token metadata is sufficient.

The application may inspect known provider files needed for token metadata and known credential stores needed for quota authentication. Reads must be bounded to documented provider locations.

### 8.3 Credential policy

- Prefer existing provider-native credentials.
- Do not copy raw provider access tokens into Swift presentation state.
- Do not log secrets.
- Explicitly redact sensitive HTTP/RPC headers and payload fields in diagnostics.
- Browser cookie import, if added for Cursor fallback, is opt-in rather than silently enabled.
- Needlbar-specific persistent secrets, if ever required, belong in macOS Keychain rather than UserDefaults.

## 9. Error Handling

Errors are classified at the provider/subsystem boundary.

Minimum error categories:

- `notInstalled`
- `noUsageData`
- `requiresAuthentication`
- `authenticationExpired`
- `rateLimited`
- `networkUnavailable`
- `providerUnavailable`
- `schemaChanged`
- `permissionDenied`
- `internalError`

Rules:

- Partial results are preferred over whole-app failure.
- Provider failures cannot crash other provider modules.
- Quota failure cannot blank usage.
- Usage failure cannot blank quota.
- Stale last-known-good values are visually distinct from fresh data.
- Schema contradictions fail closed rather than inventing percentages/reset times.

## 10. Testing Strategy

### 10.1 Rust unit tests

For `needlbar-quota`:

- provider payload parsing,
- percentage normalization,
- reset timestamp parsing,
- credential resolution precedence,
- auth-expiry handling,
- retry/fallback classification,
- secret redaction,
- malformed/contradictory payload rejection.

For `needlbar-bridge`:

- schema envelope serialization,
- error envelopes,
- partial-provider results,
- panic containment,
- pointer allocation/free smoke tests.

### 10.2 Upstream usage engine contract tests

Pin `tokscale-core` to a reviewed commit.

Maintain fixtures covering at least:

- Claude sample history,
- Codex sample history,
- Cursor cached usage export.

Each engine pin upgrade runs a cross-check confirming:

- total tokens,
- input/output/cache splits,
- cost totals,
- provider IDs,
- daily aggregation.

### 10.3 Swift unit tests

`NeedlbarCore` tests cover:

- JSON decoding,
- unknown additive fields,
- usage/quota merge behavior,
- last-known-good state,
- stale-state transitions,
- Overview most-constrained quota selection,
- module setting persistence,
- numeric/date formatting.

### 10.4 UI tests / smoke tests

At minimum:

- Overview module appears by default.
- Provider modules can be enabled/disabled.
- Metric selection changes the menu-bar title.
- Popover renders partial data states.
- `requiresAuthentication` has a clear user action.
- Stale state does not erase last-known-good values.

### 10.5 Live smoke matrix

Before release, run manually with real accounts where available:

| Provider | Usage | Quota | Auth fallback |
| --- | --- | --- | --- |
| Claude | required | required | required |
| Codex | required | required | CLI fallback required |
| Cursor | required | required | explicit-connect path required |

No test fixture may contain reusable real credentials.

## 12. Distribution and Release

### v0.1 target

- macOS 14+.
- Apple Silicon first unless build verification shows universal packaging is low-cost.
- No Mac App Store requirement for v0.1.

### Distribution

Primary:

- GitHub Releases `.dmg` or `.zip`.

Secondary after the release path is stable:

- Homebrew Cask.

Updates:

- Sparkle is the preferred in-app updater once signing/appcast infrastructure is ready.

### Signing

The implementation/release plan must explicitly decide between:

- ad-hoc development distribution during pre-release,
- Developer ID signing + notarization for stable public releases.

Stable public releases should target Developer ID signing/notarization when feasible because the app accesses provider-local state and should minimize Gatekeeper friction.

## 13. Open-Source Maintenance Rules

- MIT license for Needlbar-owned source.
- Preserve all upstream notices required by embedded dependencies.
- Pin `tokscale-core`; do not silently float `main`.
- Upstream usage/parser fixes should be contributed upstream when generally applicable.
- Needlbar-specific quota/auth code stays outside `tokscale-core`.
- Provider integrations require fixtures and explicit documentation of auth/data sources.
- New providers after v0.1 must preserve the same Usage/Quota separation.

## 14. Acceptance Criteria for v0.1

Needlbar v0.1 is ready when all of the following are true:

1. The app launches as a native menu-bar app with no Dock-focused primary workflow.
2. Overview is enabled by default.
3. Claude, Codex, and Cursor provider modules can be independently enabled.
4. Claude usage/cost is populated from embedded `tokscale-core` compatible local sources.
5. Codex usage/cost is populated from embedded `tokscale-core` compatible local sources.
6. Cursor usage/cost is hydrated by the Needlbar-owned Cursor source-sync adapter into a tokscale-compatible local cache and then aggregated by the embedded engine.
7. Claude quota can be retrieved from existing valid provider authentication or produces a clear authentication-required state.
8. Codex quota can be retrieved from existing valid provider authentication with a CLI RPC fallback where appropriate.
9. Cursor quota can be retrieved through supported local/session authentication or an explicit connect/import flow.
10. Usage and quota can fail independently without erasing the other subsystem's valid data.
11. A failed refresh retains the last known good values and marks them stale.
12. No Needlbar backend, account, or telemetry is required.
13. No prompt, response, or source-code content is displayed or uploaded.
14. Rust unit tests, Swift unit tests, ABI smoke tests, and provider fixture tests pass.
15. A release artifact can be installed and run on the supported macOS baseline.

## 15. Deferred v0.2+ Directions

Potential follow-up work, explicitly outside this implementation cycle:

- project/repository attribution,
- Git commits and PR correlation,
- cost per commit / PR,
- coding-time correlation,
- provider/model efficiency analytics,
- macOS widgets,
- notifications,
- additional providers,
- export formats,
- cross-device sync,
- Windows/Linux clients.

The v0.1 architecture intentionally keeps these possible without requiring them now.
