# Cursor Session Token Paste Command Design

> **SUPERSEDED — 2026-08-26:** This document is retained as historical regression/design
> record only. The approved Cursor local-usage/dashboard amendment removes the Cursor token
> field and connection workflow, so this paste behavior is no longer an active requirement.
> See [`2026-08-26-cursor-local-usage-dashboard-quota-design.md`](2026-08-26-cursor-local-usage-dashboard-quota-design.md).

**Status:** Approved on 2026-08-26
**Scope:** Regression fix for the Cursor session-token field in Needlbar Settings
**Base contracts:** `docs/superpowers/specs/2026-08-13-needlbar-v0.1-design.md` and `docs/superpowers/specs/2026-08-25-provider-managed-browser-login-design.md`

## 1. Decision

Needlbar will install a standard AppKit `Edit` menu when the application finishes launching. The menu's Paste command is the native AppKit command:

```swift
NSMenuItem(
    title: "Paste",
    action: #selector(NSText.paste(_:)),
    keyEquivalent: "v"
)
```

The command must use a `nil` target and a `.command` key-equivalent modifier. AppKit will therefore resolve the action through the responder chain and deliver it to the currently focused control, including the Cursor `SecureField` in Settings. The fix does not add a token-specific paste implementation, clipboard reader, or alternate credential path.

The existing Cursor connection contract remains unchanged: the field is still a transient `SecureField`, `SettingsView` still passes its bound value to `CursorSessionConnectionController`, and the controller still clears the input before beginning an import. Needlbar must never read, log, persist, or inspect the token or clipboard contents.

## 2. Problem and user-visible behavior

Needlbar is an accessory-style AppKit application launched programmatically. Its Settings window contains a SwiftUI `SecureField("Cursor session token", text: ...)`. The field can be focused and its contextual menu exposes Paste, but the application has no standard Edit menu command for the system `⌘V` event. As a result, a user can be unable to paste a Cursor session token into the field.

After this change:

- opening Settings and focusing the Cursor session-token field allows `⌘V` to paste through the normal AppKit responder chain;
- the contextual menu continues to use the same native field behavior;
- typing, editing, Connect, Reconnect, Disconnect, transient clearing, and connection status behavior remain unchanged;
- no paste action runs unless a first responder accepts the native `NSText.paste(_:)` selector;
- no token value appears in diagnostics, logs, tests, documentation, or error messages.

## 3. Architecture and ownership

### 3.1 AppKit application layer

`NeedlbarApp` owns menu installation because it owns application lifecycle. A small testable installer, for example `ApplicationMenuInstaller`, builds or updates `NSApp.mainMenu` and is called from `AppDelegate.applicationDidFinishLaunching(_:)` before the app begins its normal observation and refresh tasks.

The installer must be idempotent in Needlbar's normal launch path. Needlbar starts with no main menu, so repeated installer calls must not add duplicate `Edit` menus or duplicate Paste items in that app-owned path. If a host or test supplies an application menu that already contains multiple same-title `Edit` or `Paste` items, the installer cannot prove which entries it owns and must preserve them all. It selects the first `Edit` item and, within that submenu, the first `Paste` item; it repairs only that Paste item to this exact native contract and never deletes arbitrary pre-existing menu content. Thus, exactly one `Edit` menu and one Paste item are guaranteed only for the clean app-owned path, not for arbitrary pre-existing duplicate state:

| Property | Required value |
| --- | --- |
| Action | `#selector(NSText.paste(_:))` |
| Target | `nil` |
| Key equivalent | `"v"` |
| Modifier mask | `[.command]` |

The installer may include the other ordinary Edit commands (`Undo`, `Redo`, `Cut`, `Copy`, `Delete`, and `Select All`) using their standard AppKit selectors. Those commands are presentation plumbing only; no command may read or transform provider credentials.

### 3.2 Settings and credential ownership

`SettingsView.swift`, `CursorSessionConnectionController`, and `CursorSessionBridge` remain the owners of the existing Cursor session-token flow. No production code in those types should be changed solely to handle paste. The value remains transient SwiftUI state and is still cleared when Connect or Reconnect begins. The Rust bridge and Cursor cache/session storage contracts are unaffected.

### 3.3 Test boundary

The regression test must inspect a real menu generated by the installer. It must not replace the Paste action with a fake selector, fake responder, or clipboard mock. The automated assertion is structural—action, target, key equivalent, and modifier mask—while a manual UI smoke proves that the focused real SecureField accepts `⌘V`.

## 4. Implementation contract

The implementation consists of:

- `Sources/Needlbar/App/ApplicationMenuInstaller.swift` — a main-actor AppKit menu installer with an idempotent `install(in:)` entry point;
- `Sources/Needlbar/App/AppDelegate.swift` — calls the installer from `applicationDidFinishLaunching(_:)`;
- `Tests/NeedlbarTests/ApplicationMenuInstallerTests.swift` — real `NSMenu` regression coverage.

The installer must not:

- access `NSPasteboard` directly;
- print or serialize clipboard contents;
- inspect or log the Cursor token;
- alter `SettingsView`'s binding, `SecureField`, connection controller, or bridge;
- introduce a custom key event monitor or a `⌘V` shortcut that bypasses AppKit's responder chain;
- add a provider-specific menu item or credential storage.

## 5. Testing and acceptance

### Automated regression

The test suite creates the application's actual menu structure through the installer, locates the `Edit` submenu and its Paste item, and asserts the four required properties. It calls the installer twice from a nil main-menu state and asserts that the normal app-owned path still has one `Edit` submenu and one Paste item. A separate test seeds multiple same-title `Edit` and `Paste` entries, verifies that all pre-existing entries remain, and asserts that only the first `Edit`/first `Paste` selection is repaired to the native contract. The tests must pass without accessing a real clipboard or token.

### Manual UI smoke

With a harmless non-secret fixture copied to the clipboard, launch Needlbar, open Settings, focus the Cursor session-token field, and press `⌘V`. Confirm visually that the field receives masked input. Do not click Connect or persist the fixture. Clear the field and clipboard after the smoke. Confirm that the field still clears on Connect/Reconnect and that no secret value appears in logs or diagnostics.

### Project gate

Run the focused Swift test and then the full project verification command:

```bash
swift test --filter ApplicationMenuInstallerTests
make test
```

Both commands must exit successfully. `make test` remains the release verification entry point; no change to the macOS 14 deployment target or approved provider-authentication design is permitted.

## 6. Security and privacy invariants

- The clipboard is used only by AppKit's standard responder-chain paste action after explicit user input.
- Needlbar does not call `NSPasteboard` or copy the token into another store.
- The Cursor token never enters logs, diagnostics, Rust bridge errors, test output, fixtures, or documentation.
- Existing session import and connection failure handling remain unchanged.
- The fix does not expand Cursor authentication beyond the approved explicit session-token flow.
