# Needlbar v0.2.2 Local Repository Cost Analytics Design

**Status:** Approved design draft for implementation planning.

**Scope:** v0.2.2 only. This document adds a manual, local-only analytics
surface. It does not alter the established usage, quota, export, widget, or
notification contracts.

## 1. Purpose and roadmap position

v0.2.2 follows v0.2.0 local JSON export and v0.2.1 widgets and notifications.
It turns the already-local Claude, Codex, and Cursor usage evidence into a
bounded, on-demand view of repository-attributed estimated AI cost. Its goal is
to answer, locally and conservatively:

- Which automatically observed repositories had attributable AI usage in the
  last 30 days?
- What are their tokens and estimated cost, including provider/model split?
- How much **observed AI active-session time** was present in their source
  records?
- Which local commits have a deterministic, explicitly heuristic association
  with that usage?

This is accounting and correlation, not productivity scoring. It must never
claim that an AI session caused a commit, that a commit's actual implementation
cost is known, that observed session time is human coding time, or that a model
is higher quality. The v0.1 roadmap's project/repository attribution, commit
correlation, cost-per-commit, coding-time correlation, and provider/model
efficiency directions are satisfied only to the precise extent specified here.

Pull-request association is intentionally best-effort and local-metadata-only:
it may report a number only when a local commit message contains an unambiguous
PR-number marker. It does not establish that the pull request exists, is open,
belongs to a particular forge, or contains the commit.

## 2. Product scope

### 2.1 Included

- A resizable native **Analytics** window, opened by an **Analytics…** action
  from the existing Overview surface.
- An on-demand 30-day analysis triggered when the window first opens and by its
  explicit Refresh action. There is no analytics timer, file watcher, startup
  scan, background task, or silent refresh.
- Attribution only from workspace paths that the existing local usage engine
  automatically recovered from its supported Claude/Codex/Cursor sources. The
  application does not ask the user to select a folder, crawl arbitrary home
  directories, or discover repositories independently of an observed workspace.
- Repository totals, provider/model breakdowns, observed active-session time,
  coverage, Unattributed totals, and local commit correlations.
- Read-only, bounded inspection of local Git metadata for repository roots
  reached from those observed workspaces.
- A versioned, sanitized Rust-to-Swift analytics snapshot ABI.
- In-memory last-known-good presentation while a later explicit analysis fails;
  it is marked stale and is never written as an analytics history database.

### 2.2 Explicit exclusions

v0.2.2 does not add:

- a Needlbar account, backend, telemetry, cloud sync, webhooks, or upload;
- provider authentication, provider API requests, Keychain access, login flow,
  Cursor remote hydration, or a new pricing/network request path;
- Git remote inspection, `fetch`, `push`, `ls-remote`, forge API calls,
  browser automation, `gh`/`glab` authentication, OAuth, or credentials;
- a pull-request API integration, PR title/status/author data, branch names,
  remote URLs, issue correlation, or a guarantee of PR identity;
- prompt/response/source-code display or storage, commit messages, commit
  authors, email addresses, raw session identifiers, or raw file paths;
- a persistent analytics database, automatic history collection, configurable
  correlation windows, configurable idle gaps, dashboards outside the native
  window, widgets, notifications, or export-format changes; or
- changes to the current fixed provider set or to provider usage/quota refresh
  ownership.

The v0.2.0 JSON export remains a snapshot of the existing normalized provider
state. Analytics data, repository labels, opaque IDs, commit IDs, and inferred
PR numbers are not added to that export.

## 3. User experience and truthful terminology

### 3.1 Entry and window lifecycle

The Overview popover gains one **Analytics…** action beside its existing
navigation actions. Selecting it opens or brings forward one separate,
resizable Analytics window. It does not keep the status-item popover open and
does not alter menu-bar module settings.

The first open starts exactly one analysis. While it runs, the window presents
an indeterminate local-analysis state without source paths or system errors.
Refresh is disabled while an analysis is in flight. Closing the window may
release the presentation observer but does not cancel a Rust call in a way that
would leak or retain its output; a completed result may be retained only in the
in-memory Core state for the next open.

No window open or refresh performs a provider refresh. It uses the same local
usage-source scan/pricing basis already used by usage aggregation, subject to
the pricing rule in section 8.4.

### 3.2 Presentation

The window has a fixed 30-day range ending at the analysis capture time. It
shows:

1. Repository rows, ordered by descending attributable estimated cost, then by
   stable repository ID. Each contains safe repository label, tokens, estimated
   cost, observed active AI-session time, cost/timing coverage, and an
   Unavailable state when its Git metadata could not be safely read.
2. An expandable provider/model breakdown for each repository. A model row can
   show estimated cost per 1K tokens, tokens per observed active hour, and
   response milliseconds per 1K tokens only when the relevant denominator and
   coverage are present.
3. A commit table containing local abbreviated commit IDs, committer time,
   correlated estimated AI cost, and an optional `PR #<number> (local metadata)`
   label. It never displays commit subject/body, author, branch, remote, or PR
   state.
4. An **Unattributed** row and coverage explanation. It is a first-class result,
   not silently dropped data.

Copy uses these exact meanings:

- **Estimated cost** is the existing engine's cost basis; it is not an invoice
  or subscription charge.
- **Observed active AI-session time** is the sum of timestamp-derived activity
  gaps no greater than three minutes. It is not elapsed wall time, keyboard
  time, employee time, or human coding time.
- **Correlated estimated AI cost** is a deterministic local time-window
  association. It is not causal attribution or measured cost of a commit.
- **Coverage** identifies how much eligible data carried a usable workspace,
  timestamp, pricing value, or response-duration measurement. No missing value
  is converted to zero.

Repository labels are derived only from a resolved repository root's final path
component, normalized to a bounded display label. The full path never leaves
Rust. A missing, invalid, or colliding label becomes a deterministic generic
`Repository <opaque-id-prefix>` label.

## 4. Architecture and ownership

```text
existing local provider session/cache sources
        |
        v
tokscale-core (existing streaming scan + cross-file dedup + pricing)
        |  raw workspace/session data remains in Rust
        v
additive WorkspaceSession report
        |
        v
needlbar-project-analytics (new Rust crate)
  - map observed workspace -> containing local Git repository
  - bounded read-only local commit metadata
  - deterministic correlation + sanitization
        |
        v
needlbar-bridge -> needlbar_analytics_snapshot_json()
        |
        v
NeedlbarCore analytics repository/state -> resizable Analytics window
```

### 4.1 `tokscale-core`

The pinned `vendor/tokscale-core` remains the only owner of provider session
discovery, parsing, source-message cache behavior, cross-file deduplication,
model normalization, and cost estimation. v0.2.2 adds an **additive
WorkspaceSession report** to that dependency. It must fold over the same
production streaming scan and dedup path as the existing reports; a new consumer
must not call the public materialized parsing helper and accidentally produce
different totals.

The report's Rust-only input/result may carry raw workspace keys, session IDs,
timestamps, token splits, model/provider identity, cost basis/provenance, and
optional response duration only as long as those values remain below the
sanitization boundary. It must:

- filter to the analysis range before its final aggregation;
- preserve a fixed record of whether workspace/timestamp/duration/cost was
  actually observed;
- split a session whenever its workspace changes, rather than assigning one
  mixed-workspace session to an arbitrary repository;
- use the existing three-minute idle-gap definition for active time; and
- return deterministic ordering and bounded records.

It does not run Git, infer PRs, construct Needlbar JSON, make presentation
decisions, or change existing graph/model/time-report behavior. Any submodule
revision or semantic change requires the existing fixture-parity cross-check:
Needlbar's Claude, Codex, and Cursor usage fixtures must retain parity for
tokens, model-cost aggregation, dates, and deduplication before the pin changes.

### 4.2 `needlbar-project-analytics`

A new Rust crate owns repository mapping, local Git metadata extraction,
correlation, bounds, and output sanitization. It receives only the additive
report's in-process records; it never reparses provider session files.

For each valid observed workspace, it resolves at most one containing Git
repository and maps the workspace to the deepest matching root. It performs no
home-directory walk: a repository is eligible only if an engine-observed
workspace leads to it. Nonexistent workspaces, non-Git workspaces, inaccessible
repositories, malformed metadata, and ambiguous mappings are represented in
coverage or Unattributed results without a path-bearing error.

Repository inspection uses a direct, absolute `/usr/bin/git` subprocess with a
fixed argument vector and no shell. Each invocation:

- uses only read-only discovery/log commands and explicit `-C` workspace/root
  arguments;
- disables interactive prompts and external diff execution, does not invoke
  aliases, hooks, remote commands, fetches, or credential helpers;
- has a per-process timeout, a total analysis deadline, fixed maximum stdout
  bytes, fixed maximum stderr bytes retained only for disposal, and a fixed
  maximum record count; and
- discards raw command output immediately after strict parsing and
  sanitization.

The implementation uses at most 64 distinct repositories, 500 local commits
per repository, 200 returned commit rows per repository, 1 MiB stdout and 8 KiB
stderr per subprocess, a 2-second subprocess timeout, and a 10-second total
Git-inspection budget. Reaching a cap is a safe partial result with a fixed
coverage/error code, never an unbounded retry. Rust validates every record and
rejects control characters, invalid timestamps, oversized fields, duplicate
commit IDs, and non-finite/negative counters before bridge serialization.

Raw Git output may temporarily contain commit message text solely to detect an
explicit marker. It is neither logged nor retained after parsing. The only
accepted PR markers are an ASCII decimal number in a standalone `(#<n>)` or
`PR #<n>` token, where `1 <= n <= 2_147_483_647`; a record with zero, multiple,
or malformed candidates has no PR number. The result says only that local commit
metadata contained an unambiguous number. It never derives a forge, URL,
repository owner, branch, PR title, author, or status.

### 4.3 `needlbar-bridge`

`needlbar-bridge` owns the new C-callable entrypoint, JSON envelope,
serialization, panic boundary, and Rust allocation/freeing. It owns no AppKit
or SwiftUI presentation.

```c
const char *needlbar_analytics_snapshot_json(void);
```

Ownership exactly matches the existing snapshot functions: every non-null
pointer is UTF-8 JSON owned by Rust and must be released exactly once through
`needlbar_free_string`. The new symbol is additive; no existing C declaration,
symbol, envelope, or ownership rule changes.

### 4.4 `NeedlbarCore` and `Needlbar`

`NeedlbarCore` owns analytics-envelope decoding, semantic validation,
last-known-good/stale state, in-flight serialization, fixed display formatting,
and a UI-free analytics repository protocol. It does not inspect Git,
workspace paths, raw messages, command output, or provider credentials.

`Needlbar` owns the Overview action, the separate window controller, SwiftUI
presentation, and window restoration policy. It does not parse bridge JSON by
hand, spawn Git, or encode analytics data. Widgets, notification services, and
their App Group DTO/ledger are not analytics consumers.

## 5. Correlation semantics

### 5.1 Analysis interval and eligibility

At invocation, one UTC `generatedAt` is captured. The closed analysis interval
is `[generatedAt - 30 days, generatedAt]`; all timestamps are RFC3339 UTC.
Records without a valid nonfuture timestamp belong to Unattributed coverage and
cannot be associated with a commit or active-time metric.

A WorkspaceSession fragment is eligible for repository totals when it has:

- a recognized Needlbar provider;
- a valid recovered workspace mapped to exactly one accessible local repository;
- finite nonnegative tokens and cost; and
- a timestamp in the analysis interval.

An unavailable provider stream, a parser failure, an unknown workspace, an
unresolvable repository, or a Git cap/failure never prevents other providers or
repositories from appearing.

### 5.2 Observed active AI-session time

The report groups events by workspace, client, and session and sorts by event
timestamp. Consecutive gaps no larger than **three minutes** count toward active
time; larger gaps count as zero. The metric is the sum of those observed gaps.
An isolated event has zero observed active time, not an invented duration.
Events without timestamps contribute usage only to the appropriate
Unattributed/coverage bucket and do not affect time metrics.

Response-duration performance is distinct from active time. A model's
milliseconds-per-1K metric is emitted only from positive duration and token
samples, with explicit timed-token and sample coverage. It is response
throughput, not user productivity or quality.

### 5.3 Commit assignment

For each eligible WorkspaceSession fragment ending at timestamp `E`, the
correlator considers local commits in the same resolved repository whose
**committer** timestamp `C` satisfies:

```text
E <= C <= E + 4 hours
```

It chooses the earliest such commit, breaking equal timestamps by full commit
OID byte order. A fragment is assigned to at most one commit. Multiple
fragments may be assigned to one commit. Usage totals stay attributed to the
repository whether or not a commit is found.

If `E + 4 hours > generatedAt`, the fragment is `pendingCommitWindow` rather
than `noEligibleCommit`: a later manual analysis may see a newly made local
commit and change that correlation. Otherwise no matching commit is
`noEligibleCommit`. These cases are counted separately in coverage. Git history
rewrites, amended commits, clock skew, and commits made outside the window may
also change a later manual result; no result is durable history.

The cost shown for a commit is the sum of its singly assigned fragments' existing
estimated costs. There is no division by line count, changed file, author, PR,
or repository activity. Commits with no assigned fragment may be omitted from
the displayed commit list; the summary must disclose correlated-commit coverage
and must not use their count as a denominator for an unstated average.

## 6. Analytics schema and sanitization

The analytics ABI uses a dedicated envelope, independent of the existing
`needlbar.v1` usage/quota envelope:

```json
{
  "schemaVersion": "needlbar.analytics.v1",
  "ok": true,
  "generatedAt": "2026-09-01T12:00:00.000Z",
  "data": {},
  "errors": []
}
```

`schemaVersion` is exactly `needlbar.analytics.v1`. `generatedAt` is an exact
millisecond RFC3339 UTC timestamp. `ok` is false only when no structurally valid
analytics payload can be produced; partial repository/provider/Git outcomes use
`ok: true`, `data`, coverage, and fixed safe errors. Unknown schema versions,
invalid UTF-8, invalid numbers, oversized payloads, or invalid ordering fail
closed in Core.

`data` contains exactly these conceptual fields:

```text
analysisRange: { start, end }                         // exact UTC timestamps
repositories: [RepositoryAnalytics]                   // <= 64
unattributed: AttributionBucket
coverage: AnalyticsCoverage
```

Each `RepositoryAnalytics` contains:

```text
repositoryID: String              // opaque, stable only for this snapshot
label: String                     // bounded root-basename label or generic label
state: available | unavailable
usage: UsageAggregate              // decimal-string counters and cost
observedActiveTimeSeconds: String  // nonnegative decimal integer
providerModels: [ProviderModelAnalytics]
commits: [CommitAnalytics]         // <= 200
coverage: RepositoryCoverage
```

`UsageAggregate` has `inputTokens`, `outputTokens`, `cacheReadTokens`,
`cacheWriteTokens`, `reasoningTokens`, `totalTokens`, and `estimatedCostUSD`.
All token fields are nonnegative canonical base-10 integer strings. Cost is a
nonnegative canonical decimal string: no exponent, sign, locale separator, or
insignificant trailing fractional zeroes. The bridge never emits binary floats.

`ProviderModelAnalytics` has fixed Needlbar `provider` (`claude`, `codex`, or
`cursor`), a bounded sanitized model identifier, `usage`, optional
`costPer1KTokens`, optional `tokensPerObservedActiveHour`, optional
`millisecondsPer1KTokens`, and its cost/timing coverage. A missing denominator
is `null`, never zero. Unknown/dynamic upstream names that fail the identifier
allowlist are folded into fixed `Other model` coverage instead of being exposed
verbatim.

`CommitAnalytics` has only `commitID` (12 lowercase hexadecimal characters),
`committedAt`, `correlatedUsage`, optional `pullRequestNumber`, and correlation
coverage. `pullRequestNumber` is a JSON integer in the accepted range or
`null`. It has no message, author, email, branch, repository URL, or full OID.

`AttributionBucket` and `AnalyticsCoverage` use the same aggregate format plus
fixed counters/reason codes. Reason codes are limited to:

```text
missingWorkspace, invalidWorkspace, nonRepositoryWorkspace,
ambiguousRepository, repositoryUnavailable, missingTimestamp,
missingCost, missingDuration, noEligibleCommit, pendingCommitWindow,
recordLimitReached, gitOutputLimitReached, gitTimedOut, gitUnavailable
```

`errors` has fixed `{ scope, code }` values only. `scope` is one of `usage`,
`repository`, `git`, or `analytics`; `code` is a fixed allowlisted code derived
from the above conditions. There is no path, command line, stderr, raw provider
error, account data, or user-controlled message field.

The complete UTF-8 analytics document is capped at 256 KiB. Rust sorts
repositories by attributable cost descending then opaque ID, provider/model rows
by provider/model, commits by committer time descending then full internal OID,
and reason/error arrays lexicographically. Core validates that ordering instead
of silently resorting malformed bridge data.

At no point may a raw workspace path, repository root path, remote URL, branch,
commit author/email/message, session ID, prompt, response, source content,
credential, account identifier, full commit OID, or raw subprocess output cross
the Rust bridge boundary. These values are also excluded from diagnostics,
widgets, notifications, logs, and v0.2.0 export.

## 7. Failure, freshness, and concurrency

Analytics refresh is serialized independently from usage and quota refresh. A
manual analytics refresh must not block or trigger provider usage/quota refresh,
authentication, or notification evaluation. Only one analytics bridge call can
be in flight; later window opens join the current presentation state rather than
starting a second scan.

A successful result is `fresh` at its captured `generatedAt`. If a later
explicit refresh fails after a success, Core retains that in-memory successful
payload as `stale`, attaches only fixed safe failure copy, and permits another
manual retry. If no success exists, the window displays `Unavailable`. Closing
or quitting the app discards analytics state; there is no analytics database or
last-result file.

Partial results are valid and fresh for the providers/repositories they contain.
They must preserve separate coverage for unavailable Git metadata and
Unattributed source records rather than making the whole analysis unavailable.
The screen must include the analysis timestamp and local-only explanation so a
user cannot mistake it for continuously updated source control state.

## 8. Privacy, process, and pricing constraints

The v0.1 local-first policy remains authoritative. Analytics adds bounded local
reads only from existing provider usage sources and from Git metadata reachable
from an automatically observed workspace. It creates no new provider, forge,
credential, browser, or telemetry boundary.

The repository subprocess helper uses explicit argument arrays, explicit
environment allowlisting, wall-clock deadlines, byte caps, record caps, and
termination/reap handling. It never accepts a command string, shell fragment,
Git alias, or user-entered ref. A failure to reap a child is an analytics failure
that prevents starting another analytics subprocess until cleanup completes; it
does not broaden process ownership or kill unrelated processes.

Existing cost calculation can use a cached pricing dataset and, in its current
engine implementation, may refresh that dataset under its established behavior.
v0.2.2 must not add a second pricing request or silently expand that behavior.
The implementation plan must choose and test one explicit policy: reuse the
already-established usage cost basis, or invoke the additive report in existing
cache-only/local-pricing mode. The analytics UI labels cost coverage/basis and
never claims that a fresh remote model-price lookup occurred.

## 9. Compatibility invariants

v0.2.2 must leave all of the following byte/API/behavior contracts unchanged:

- existing usage and quota C symbols, `needlbar.v1` envelope, Swift DTOs,
  independent refreshes, last-known-good behavior, and provider boundaries;
- v0.2.0 snapshot export schema, fixed provider order, no-reread capture,
  local-only atomic writer, and excluded-data guarantees;
- v0.2.1 widget projection schema, extension isolation, App Group file,
  WidgetKit update behavior, notification ledger, alert policy, and provider
  fetch ownership; and
- existing AppKit status-item, authentication, Settings, and package/signing
  behavior except for the additive Overview Analytics… action and new window.

There is no analytics path from WidgetKit, notifications, Settings export, or a
background application launch. The main app is the only process allowed to call
the analytics bridge.

## 10. Verification and acceptance criteria

Implementation requires fixture-first coverage for the new report, correlator,
bridge, Core, and window seams. At minimum, tests prove:

1. The additive tokscale report uses the same streaming/dedup path and retains
   fixture parity with existing Claude, Codex, and Cursor usage totals, dates,
   model costs, and cross-file deduplication.
2. Workspace changes split session fragments; missing/invalid workspace or
   timestamps become explicit Unattributed coverage without path exposure.
3. Three-minute active-time boundaries, isolated events, overlapping sessions,
   missing duration, model response-throughput coverage, and no productivity
   inference are correct.
4. Repository matching chooses only automatically observed workspace ancestors,
   deepest matching roots deterministically, and safely handles absent,
   non-Git, inaccessible, symlink/worktree, and ambiguous metadata cases.
5. The Git helper has no shell, no remote invocation, bounded fixed arguments,
   timeout/output/record caps, reaping behavior, and never exposes raw stdout or
   stderr. Cap and timeout outcomes are safe partial results.
6. Commit assignment uses committer time, the inclusive four-hour boundary,
   earliest-commit and OID tie breaks, one assignment per fragment,
   `pendingCommitWindow`, and `noEligibleCommit` exactly as specified.
7. Only unambiguous local PR markers yield a bounded number; zero/multiple/
   malformed markers yield `null`; no forge inference is made.
8. DTO/envelope schema, exact timestamps, canonical numeric strings, 256 KiB
   cap, fixed ordering, nullable metrics, partial errors, and malformed/unknown
   schema rejection are covered.
9. Privacy canaries prove raw paths, remote URLs, branches, authors, messages,
   session IDs, prompts, source content, credentials, account IDs, full OIDs,
   and subprocess output cannot enter ABI JSON, diagnostics, export, widget, or
   notification data.
10. Core serializes in-flight work, retains only in-memory stale last-good data,
    does not trigger usage/quota/authentication/network work, and isolates
    analytics failures from all other streams.
11. The Overview action opens one resizable Analytics window, Refresh behavior
    is correct, unavailable/stale/partial coverage copy is truthful, and close/
    reopen behavior has no duplicate observer or bridge call.
12. Existing full `make test` remains green, alongside focused Rust/Swift/ABI
    tests and the required pinned-submodule fixture parity check for every
    vendor change.

v0.2.2 is accepted only when a local fixture demonstrates repository totals,
Unattributed coverage, an exact four-hour commit assignment, a pending window,
and sanitized PR-number extraction without any remote/network/authentication
activity; all privacy canaries and prior-version regression suites must pass.
