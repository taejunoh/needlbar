# Needlbar v0.3 System Monitor Design

**Status:** Draft for user review.

**Scope:** v0.3.0 system-monitoring expansion. This feature makes Needlbar a
single replacement for the current Stats-style menu-bar monitor while
preserving the existing Claude, Codex, Cursor usage, quota, export, widget, and
notification contracts.

## 1. Purpose and roadmap position

Needlbar currently exposes AI usage and quota information, but a Mac without a
notch may have no convenient place for the product's status item to remain
visible. Users should not need a second menu-bar utility just to see basic
machine health. v0.3 adds a configurable system-monitoring surface so the same
Needlbar item works on Macs with or without a notch and combines system state
with AI usage state.

The feature is intentionally local-first. System metrics are collected on the
Mac, shown in the menu bar and popover, and are not added to the existing JSON
export or repository analytics paths. Existing provider refresh ownership and
last-known-good semantics remain unchanged.

## 2. Product scope

### 2.1 Included

- A configurable module registry containing CPU, RAM, disk, network, battery,
  and AI usage modules.
- Per-module visibility and order settings.
- Adaptive menu-bar presentation that uses text when space permits and compact
  icons/core values when space is constrained by a notch or neighboring items.
- A popover anchored directly below the Needlbar status item. Clicking outside
  the popover dismisses it.
- A one-second presentation/collection tick for system metrics.
- A combined popover with detailed CPU, RAM, disk, network, battery, and
  provider-level AI sections.
- Optional local and public IP display. Transfer speed is on by default;
  IP display is controlled from settings. Public-IP lookup is disabled unless
  the user enables it and is performed through an injected HTTPS provider using
  `https://api64.ipify.org?format=json`, with bounded caching and timeout
  behavior. The endpoint is not user-editable.
- Provider-level AI configuration: show/hide, order, and displayed value
  (`usage`, `remaining`, `cost`, or `connection status`) for Claude, Codex, and
  Cursor.
- Explicit `fresh`, `stale`, and `unavailable` states for each module.
- Deterministic unit and UI-contract tests using injected metric providers and
  fixed fixtures; no live hardware or public network is required in tests.

### 2.2 Explicit exclusions

v0.3 does not add:

- process-level or per-application CPU/memory attribution;
- fan speed, temperature, GPU, or sensor controls;
- a background history database, charting history, telemetry, cloud sync, or
  account system for system metrics;
- system metrics to the v0.2.0 JSON export, widgets, notifications, or local
  repository analytics payloads;
- provider API polling, new authentication flows, or a change to the existing
  provider set;
- arbitrary filesystem crawling, shell commands, or privileged daemons; or
- a native macOS 14 acceptance claim. That external acceptance matrix remains
  deferred and is tracked separately in `docs/STATUS.md`.

## 3. User experience

### 3.1 Menu-bar presentation

Only enabled modules participate in the menu-bar item. The renderer measures
the status-item width and selects one of two deterministic layouts:

1. **Expanded:** short labels and values, for example `CPU 24%  RAM 79%  ↓
   50 KB/s  AI 41%`.
2. **Compact:** module icons plus the single most important value for each
   enabled module. The compact layout never relies on a notch being present.

The configured module order is retained in both layouts. When a value is
unavailable, the module keeps its slot and renders a neutral unavailable
glyph/status rather than shifting unrelated values.

### 3.2 Popover

The existing status-item presenter opens one medium-width popover whose top edge
starts immediately below the status item. It uses the existing outside-click
dismissal and generation-safe presentation seams. The popover contains all six
modules in configured order, with a disclosure row for details:

- **CPU:** total usage and per-core usage when available.
- **RAM:** used/free memory, swap, and memory pressure.
- **Disk:** per-volume used/free space and read/write throughput.
- **Network:** upload/download throughput, then local/public IP when enabled.
- **Battery:** level, charging state, and health when available.
- **AI:** Claude, Codex, and Cursor rows using each provider's configured
  value, plus connection/error state.

The popover always contains all six modules, even when a module is hidden from
the menu bar. This keeps the popover a complete Stats replacement while the
menu-bar toggles control only which values consume scarce status-item space.
Its sections show stable error states and the other sections continue rendering
their last-known-good or fresh values.

### 3.3 Settings

Settings adds a **Menu bar modules** section with:

- menu-bar visibility toggles for the six top-level modules;
- drag-to-reorder controls;
- the public-IP toggle under Network;
- per-provider AI visibility, order, and displayed-value selection; and
- a concise note that public-IP lookup requires an external HTTPS request.

Settings changes are persisted locally and applied on the next snapshot without
restarting Needlbar.

## 4. Architecture and ownership

```text
macOS system APIs / URLSession (optional public IP)
                |
                v
SystemMetricsService (Swift)
                |
existing Rust usage/quota snapshots --+
                                       v
                              CombinedSnapshotStore (Swift)
                                       |
                     +-----------------+------------------+
                     v                                    v
              MenuBarModuleRenderer                  Overview/Popover
```

### 4.1 SystemMetricsService

`SystemMetricsService` is a Swift protocol-backed actor/service. Concrete
collectors use macOS APIs for CPU, memory pressure, mounted-volume capacity,
network byte counters, battery/charging state, and interface addresses. The
service owns no AppKit views and emits immutable `SystemMetricsSnapshot`
values.

The one-second timer is owned by this service. It may coalesce work when the
application is suspended, but each resumed tick produces a monotonic capture
timestamp. Public-IP lookup is a separate injected dependency: it is never
called by the one-second timer, uses a minimum five-minute cache, and has a
two-second timeout. Local IP collection remains synchronous with the normal
system snapshot.

### 4.2 CombinedSnapshotStore

`CombinedSnapshotStore` merges the latest system snapshot with the existing
Rust usage/quota state. It does not trigger provider refreshes on every system
tick. Each module carries its own freshness timestamp and availability state,
so a failed disk read cannot erase a valid AI snapshot and a provider error
cannot erase valid CPU data.

The store exposes a single immutable view to AppKit presenters and to future
widget/notification consumers. It never exposes raw command output, provider
payloads, repository paths, session IDs, or credentials.

### 4.3 Existing layers preserved

- Swift/AppKit continues to own status-item presentation and settings.
- `NeedlbarCore` continues to own normalized state, scheduling, and
  last-known-good behavior.
- Rust continues to own provider usage/quota discovery, parsing, aggregation,
  and pricing.
- `needlbar-bridge` remains a serialization boundary only and does not collect
  system metrics or contain presentation logic.

## 5. Data model

The Swift model introduces these bounded, `Sendable` values:

- `SystemMetricsSnapshot`: capture timestamp plus CPU, RAM, disk, network,
  battery, and IP values.
- `MetricAvailability`: `fresh`, `stale`, or `unavailable` with a stable,
  user-safe code and no raw paths or command output.
- `MenuBarModuleID`: `cpu`, `memory`, `disk`, `network`, `battery`, `ai`.
- `MenuBarModuleConfiguration`: ordered IDs, visibility, compact-display
  policy, public-IP flag, and provider display preferences.
- `CombinedUsageSnapshot`: existing AI usage/quota DTOs plus the system metric
  snapshot; it is presentation state, not an export schema.

Numeric values use canonical units and formatting: percentages are 0–100 with
bounded precision, byte rates use binary units, storage uses binary capacity
units, and timestamps are absolute instants. Unknown values remain unknown and
are never converted to zero.

## 6. Error handling and privacy

- System API failures become module-local stable codes and `unavailable` or
  `stale` states.
- Public-IP DNS/TLS/HTTP/timeout failures are collapsed to a user-safe
  `publicIPUnavailable` state. Response bodies are bounded and discarded after
  parsing the address.
- The one-second loop is supervised; a collector failure cannot terminate the
  menu-bar presenter or the provider refresh scheduler.
- Local and public IP values remain in memory for display only. They are not
  logged, exported, included in analytics, or sent to a provider.
- No additional permission prompt is required for the included system APIs.
  The settings copy makes the external nature of public-IP lookup explicit.

## 7. Verification plan

The implementation plan must add focused tests for:

1. deterministic system metric conversion and unit formatting;
2. independent fresh/stale/unavailable transitions and last-known-good merge;
3. one-second tick scheduling without provider refresh amplification;
4. public-IP toggle, five-minute cache, timeout, and redaction behavior;
5. module visibility/order persistence and adaptive expanded/compact rendering;
6. popover anchoring directly below the status item and outside-click dismissal;
7. AI provider display preferences and unavailable provider states; and
8. existing Rust bridge, export, widget, notification, package, and analytics
   contracts remaining unchanged.

The project-wide `make test` command remains the release gate. Native macOS 14
Widget Gallery/App Group and notification-permission acceptance is a separate
maintainer-only gate and is intentionally deferred for this feature cycle.

## 8. Success criteria

The v0.3 feature is successful when a user can uninstall or hide Stats and, on
both notched and non-notched Macs:

- keep the selected system and AI values visible in the menu bar;
- open one anchored popover to inspect the complete selected dashboard;
- change module visibility, order, and AI display values without restarting;
- understand unavailable or stale data without guessing; and
- use the product without any new account, provider credentials, or telemetry.
