# Needlbar v0.2.0 Local JSON Export Design

**Status:** User-approved design; implementation has not started.

**Scope:** v0.2.0 only.

## 1. Roadmap Position and Purpose

The approved roadmap order is:

1. v0.2.0 — local JSON export.
2. v0.2.1 — macOS widgets and notifications.
3. v0.2.2 — project, commit, and pull-request cost analytics.

This document defines only v0.2.0. It adds an explicit local export for automation and backup of the currently normalized Needlbar snapshot. It does not add history collection, analytics, background export, or any new provider integration.

## 2. User Experience

Settings contains a **Data Export** section with one **Export snapshot…** action. There is no Overview export action, menu-bar shortcut, automatic export, export schedule, or format picker.

Selecting the action:

1. Captures the current in-memory provider snapshots immediately, once, through the actor-isolated `ProviderSnapshotStore`.
2. Does not trigger a refresh, provider login, Keychain access, network request, or Rust bridge call.
3. Shows an `NSSavePanel` for a JSON file with the default filename `Needlbar-Snapshot-yyyyMMdd'T'HHmmssSSS'Z'.json` rendered from the UTC capture time.
4. Writes the already captured snapshot only after the user confirms a destination.

The action is disabled while an export is in flight. Cancelling the save panel is a no-op. A completed commit presents `Exported`; any failure before commit presents exactly `Could not export snapshot.` A parent-directory durability-finalization warning after commit is still success and is not shown to the user. The UI never exposes a destination path, system error text, or underlying failure detail.

## 3. Architecture and Ownership

### 3.1 NeedlbarCore

`NeedlbarCore` owns the export contract and implementation:

- a versioned export DTO,
- the immutable `ExportCapture` value produced by `ProviderSnapshotStore`,
- `SnapshotExporter`, which maps an `ExportCapture` to the DTO,
- deterministic JSON encoding, and
- atomic, private local-file writing through an injected writer seam.

`ProviderSnapshotStore` is the single actor-isolated capture boundary. Its capture operation reads all three providers (`claude`, `codex`, and `cursor`) in one actor turn and returns one immutable `ExportCapture` containing one `exportedAt` and exactly one state for each provider. Each captured provider state contains:

- `usage`, `quota`, `usageStatus`, and `quotaStatus`;
- independent `usageLastSuccessfulAt` and `quotaLastSuccessfulAt` values; and
- `everUpdated` plus nullable `updatedAt`.

Conceptually, the value has the following shape; the provider collection is materialized in the fixed order shown rather than reread from the store:

```swift
struct ExportCapture: Sendable {
    let exportedAt: Date
    let providers: [ProviderExportState] // exactly claude, codex, cursor
}
```

`everUpdated` is false and `updatedAt` is `null` until the provider has its first mutation, whether that mutation is a successful stream update or a recorded failure. Thereafter `everUpdated` is true and `updatedAt` is the UTC time of the latest mutation. The bit is retained in the capture to distinguish an untouched provider from one with any update; it is internal capture state and is not serialized.

The exporter accepts only the `ExportCapture` passed to it. It has no store or clock reference and never rereads state while mapping or encoding. `ProviderSnapshotStore` exposes each provider's independent last-success timestamps in the capture; the exporter does not infer either value from `updatedAt`.

Exported providers are always ordered `claude`, `codex`, `cursor`, regardless of enabled menu-bar modules, currently visible UI, available data, or refresh outcome.

### 3.2 NeedlbarApp

`NeedlbarApp` owns `NSSavePanel` presentation and the fixed success/failure/cancel UI states. The App action receives three injectable seams:

- `SavePanelPresenter`, which presents a save panel and returns a selected URL or cancellation;
- `CoreExportAction`, which receives the already captured `ExportCapture` and the exact user-confirmed destination URL and returns commit success or failure; and
- `CaptureClock`, which supplies the capture time once at action start.

The production composition root constructs the concrete `NSSavePanel` presenter; tests inject a fake presenter. The production presenter enforces the `.json` extension before the user can confirm, then returns the exact URL confirmed by the user. The App action validates that a returned URL is a file URL whose extension is `.json` before invoking Core; a fake or other nonproduction presenter returning any other extension fails safely without invoking the writer or creating a file. App and Core never rewrite or normalize the confirmed URL, and the App action invokes Core with the single capture without asking Core or the provider store to recapture. App code does not encode JSON, inspect data, choose file permissions, or receive raw write errors.

The production save-panel presenter configures exactly:

```swift
panel.allowedContentTypes = [.json]
panel.allowsOtherFileTypes = false
panel.nameFieldStringValue = defaultFilename // already ends in .json
```

The panel enforces `.json` before confirmation; it does not confirm a non-JSON filename. After confirmation, the presenter returns that exact URL unchanged, and App/Core pass it through unchanged. Cancellation remains a no-op.

### 3.3 Unchanged Boundaries

The export reads only the current Swift normalized state. It makes no Rust, C ABI, provider, authentication, Keychain, filesystem-source, or network change. It does not call a refresh or create any new diagnostic scan.

The existing provider boundaries remain unchanged. In particular, Cursor remains local-cache-only for usage and has no in-app quota integration, credential flow, private endpoint request, or remote synchronization. Under this export contract, Cursor quota data is always `null`.

## 4. Version 1 JSON Contract

The exported document is UTF-8 JSON with lexicographically sorted object keys and exactly one trailing newline. Encoding is a pure function of one immutable `ExportCapture`; the same capture therefore produces byte-identical output. Its top-level object is:

```json
{
  "exportedAt": "2026-08-29T12:34:56.000Z",
  "providers": [],
  "schemaVersion": 1
}
```

- `schemaVersion` is the JSON number `1`.
- `exportedAt` is the one capture time, encoded as an RFC3339 UTC timestamp in the exact form `yyyy-MM-dd'T'HH:mm:ss.SSS'Z'`.
- `providers` is always an array of exactly three entries in fixed `claude`, `codex`, `cursor` order.

All exported timestamps (`exportedAt`, `updatedAt`, `lastSuccessfulAt`, and `resetsAt`) use that exact millisecond RFC3339 UTC form. Calendar dates use the exact `YYYY-MM-DD` form. The save-panel default filename is exactly `Needlbar-Snapshot-yyyyMMdd'T'HHmmssSSS'Z'.json`, with the same UTC capture time and no spaces.

Each provider entry has this shape:

```json
{
  "provider": "claude",
  "quota": {
    "data": null,
    "status": {
      "errorCode": null,
      "lastSuccessfulAt": null,
      "state": "unavailable"
    }
  },
  "updatedAt": null,
  "usage": {
    "data": null,
    "status": {
      "errorCode": null,
      "lastSuccessfulAt": null,
      "state": "unavailable"
    }
  }
}
```

`updatedAt` is `null` in this example because that provider has not been mutated; it becomes a timestamp after its first mutation. `provider` is one of `claude`, `codex`, or `cursor`. Both `usage` and `quota` always contain `status` and `data`; `data` is nullable independently for each stream.

Each stream status has exactly these fields:

- `state`: one of `fresh`, `stale`, `unavailable`, `requiresAuthentication`, or `error`.
- `lastSuccessfulAt`: the stream-specific timestamp in the exact UTC form above or `null`.
- `errorCode`: `null` unless the state is `error`; an error state uses the generic fixed value `refreshFailed`.

No raw or user-facing error message is exported. `requiresAuthentication` and `unavailable` do not add provider-specific codes.

### 4.1 Usage Data

When `usage.data` is present, it contains `allTime`, `today`, `last7Days`, `last30Days`, and `last7DaysDaily`.

`allTime` maps the current top-level `UsageSnapshot` counters directly: its `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `totalTokens`, and `estimatedCostUSD` values come from the corresponding top-level fields, not from a period approximation. `today`, `last7Days`, and `last30Days` map their existing `UsagePeriod` values. Each usage-period object has these decimal-string fields:

```json
{
  "cacheReadTokens": "0",
  "cacheWriteTokens": "0",
  "estimatedCostUSD": "0",
  "inputTokens": "0",
  "outputTokens": "0",
  "totalTokens": "0"
}
```

All token splits and totals are non-negative base-10 integer strings. `estimatedCostUSD` is a non-negative canonical POSIX decimal string and is never encoded as a JSON number.

Every exported nonnegative decimal string uses the same canonical form: no exponent, no sign, no locale separators, no leading zeroes except for zero, and insignificant trailing fractional zeroes removed. A value with no nonzero digits is encoded as `"0"`; otherwise the form is `0` or a nonzero integer, optionally followed by `.` and fractional digits ending in a nonzero digit. Negative or non-finite values fail validation before file creation; otherwise equivalent values are normalized to this form rather than rejected for insignificant trailing zeroes.

`last7DaysDaily` is an array of chronological objects. Each object contains `date` as a valid, exact `YYYY-MM-DD` calendar-date string and `totalTokens` as a non-negative base-10 integer string. Dates must be strictly ascending in calendar order, with no duplicate date. It preserves each available daily point, including legitimate zero-token days; the exporter does not sort or deduplicate them.

### 4.2 Quota Data

When `quota.data` is present for Claude or Codex, it contains:

```json
{
  "windows": [
    {
      "id": "claude.session",
      "resetsAt": "2026-08-29T14:00:00.000Z",
      "usedPercent": 42.5
    }
  ]
}
```

The v1 window-ID allowlist is fixed and provider-scoped:

- Claude: `claude.session`, `claude.weekly`;
- Codex: `codex.primary`, `codex.secondary`; and
- Cursor: no quota windows; `quota.data` is always `null`.

Each serialized window has an allowlisted `id`, a finite `usedPercent` JSON number in the inclusive range `0...100`, and `resetsAt` as an exact UTC timestamp or `null`. Unknown, arbitrary, or provider-supplied identifiers are rejected and never serialized. Window titles are intentionally omitted; they are presentation copy rather than an automation/backup contract. If a capture contains Cursor quota data or an unknown/mismatched window identifier, validation fails safely before any file is created.

## 5. Validation and File Safety

The export is local-only and user-initiated. It must never include secrets, tokens, cookies, credentials, account identifiers, raw local paths, provider responses, diagnostic messages, prompts, assistant responses, source code, or source-content-derived text.

Core validates the complete immutable capture and encodes the complete JSON bytes before creating any file. Validation includes provider order/identity, exact daily-date syntax and calendar validity, strict ascending daily dates with no duplicates, nonnegative token and cost values, finite quota percentages in `0...100`, provider-scoped allowlisted window IDs, exact timestamp forms, and the Cursor quota-null rule. Invalid, out-of-order, or duplicate daily points are rejected; the capture is not silently sorted or deduplicated. Any validation or encoding failure occurs before temporary-file creation and leaves the destination untouched.

The writer is injected behind a testable `SnapshotFileWriter` seam, for example:

```swift
protocol SnapshotFileWriter: Sendable {
    func writeAtomically(_ bytes: Data, to destination: URL) throws -> AtomicWriteResult
}

enum AtomicWriteResult: Sendable {
    case committed
    case committedWithDurabilityWarning
}
```

The production writer accepts only a local file URL. It creates a randomized sibling temporary filename in the destination's parent directory with exclusive creation (`O_CREAT|O_EXCL`) and mode `0600`, applies `fchmod(0600)`, writes all encoded bytes, and `fsync`s the temporary file. The atomic rename of that sibling to the destination is the commit point; the destination is never opened, truncated, or written directly. A temporary file in another directory, a cross-volume move, and a copy/delete fallback are forbidden. If same-directory atomic rename is unavailable, the write fails before commit.

Before the commit point, every failure preserves an existing destination. The writer attempts best-effort removal of its exact temporary path. If cleanup also fails, it records a recoverable internal cleanup condition and returns failure without claiming that the temporary path is gone; it never performs broad-directory cleanup. After a successful atomic rename, the final file has mode `0600`. The writer then attempts to open, `fsync`, and close the containing parent directory. Any failure in that post-rename durability-finalization sequence is an internal durability warning: replacement has already committed, the writer returns success-with-warning, and App presents `Exported`. The warning is not exposed as a path or system error.

The App maps all pre-commit validation, encoding, and writer failures to `Could not export snapshot.`

## 6. Testing Contract

Implementation must cover:

- deterministic lexicographic key ordering, exact timestamp forms, canonical decimal strings, byte-identical encoding for the same capture, and one trailing newline;
- exact version-1 schema, fixed provider order, nullable independent streams, stream-specific last-success timestamps, top-level `UsageSnapshot` counter mapping in `allTime`, token/cost string encoding, and quota title omission;
- fresh, stale, unavailable, requires-authentication, and error states, including `refreshFailed` only for the error state;
- an actor-isolated capture containing all three provider states, one `exportedAt`, independent last-success timestamps, untouched-provider `everUpdated=false`/`updatedAt=null`, and proof that the exporter does not reread;
- partial provider data and disabled UI modules without omitting any provider;
- privacy canaries proving the excluded data categories cannot enter exported JSON;
- pre-file validation rejection for malformed, out-of-order, or duplicate daily dates, negative costs, non-finite or out-of-range percentages, unknown/mismatched window IDs, and non-null Cursor quota data;
- atomic write success, randomized sibling temporary-file creation with mode `0600` and `fchmod`, replacement success, no direct destination write, no cross-volume fallback, and pre-rename failures that preserve an existing file;
- best-effort temporary cleanup, including an injected cleanup failure that leaves only an exact, recoverable temporary path and does not change the destination;
- post-rename parent-directory open, `fsync`, or close failure reported as an internal durability warning while still returning committed success;
- `NSSavePanel` default filename, `allowedContentTypes == [.json]`, `allowsOtherFileTypes == false`, production pre-confirmation `.json` enforcement, exact confirmed-URL preservation, and safe rejection of a non-JSON URL from a fake presenter;
- injected save-panel presenter, Core export action, and capture clock seams; production-only `NSSavePanel` construction;
- disabled in-flight action, cancel no-op, `Exported` success state, and the fixed failure copy without a path or system message; and
- project-wide `make test` verification.

## 7. Explicit Exclusions

v0.2.0 does not add:

- CSV, multiple formats, format selection, automatic exports, scheduled exports, cloud sync, a backend, telemetry, or a history database;
- refresh, login, network, Keychain, Rust bridge, C ABI, or provider-authentication work as part of export;
- provider additions, Cursor remote usage/quota access, browser-profile access, or Cursor credential handling;
- macOS widgets or notifications, which are scoped to v0.2.1; or
- project/repository attribution, Git commit or pull-request correlation, cost-per-commit/PR, coding-time, or model-efficiency analytics, which are scoped to v0.2.2.

## 8. Acceptance Criteria

1. Settings is the only export entry point and presents one JSON-only `Export snapshot…` action with the exact panel configuration; production enforces `.json` before confirmation and passes the exact confirmed URL unchanged.
2. Export creates one actor-isolated immutable capture of all three providers immediately, with one `exportedAt`, independent stream last-success values, and no reread or refresh, authentication, network activity, or Rust bridge work.
3. The output follows the version-1 contract, including fixed provider order, sorted keys, exact UTC millisecond timestamps, canonical decimal strings, and one trailing newline.
4. Usage and quota preserve their independent data, status, and last-success values; `allTime` maps the current top-level `UsageSnapshot` counters, daily points are strict ascending with no duplicates, and Cursor quota data remains `null`.
5. Exported data is privacy-safe and contains no excluded data category, raw error message, or arbitrary window identifier.
6. Validation and encoding complete before any file creation. Successful output is atomically written through a same-directory randomized `0600` temporary file; pre-commit failures preserve any existing output, while any post-rename parent-directory durability-finalization failure is only a warning.
7. The UI exposes only `Exported` or `Could not export snapshot.` after a confirmed panel result, while cancellation does nothing.
8. The full automated test suite passes before implementation is considered complete.
