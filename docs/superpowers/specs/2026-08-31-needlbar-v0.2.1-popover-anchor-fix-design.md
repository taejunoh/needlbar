# Needlbar v0.2.1 Popover Anchor Fix Design

**Date:** 2026-08-31

**Status:** Approved approach; written review pending
**Scope:** Correct the existing menu-bar popover anchor without redesigning its content or window type.

## Problem and Evidence

Needlbar currently calls `NSPopover.show(relativeTo:of:preferredEdge:)` with the status
button's bounds and `.minY`. On the current macOS 26 host, a bounded native probe confirmed
that the actual `NSStatusBarButton` has `isFlipped == true`. In that coordinate system,
`.minY` is the button's visual top, so the popover body extends through the menu-bar region
instead of beginning below the clicked icon. User screenshots reproduce that geometry.

This defect is independent of the outside-click fallback. The fallback is retained unchanged.

## Approved Correction

Keep `NSPopover`, the existing status-item ownership, `.transient` behavior, and the global
outside-click fallback. Select the preferred edge from the positioning view's coordinate system:

- flipped button: `.maxY`;
- non-flipped button: `.minY`.

This makes the edge mean the visual bottom in either coordinate system and avoids hard-coding
macOS 26 behavior into the generic status-item handle. No screen arithmetic, manual offset,
`NSScreen.main`, activation change, custom panel, or SwiftUI layout change is introduced.

AppKit may still choose another edge when the popover cannot fit. Native acceptance therefore
uses the normal case with sufficient space below the menu bar and records the clicked button's
own screen rather than assuming the primary display.

## Tests and Native Acceptance

Follow test-first implementation:

1. Add a pure edge-selection test that fails before implementation and proves
   `isFlipped == true` maps to `.maxY` and `false` maps to `.minY`.
2. Keep all existing menu-bar, outside-click, widget, provider, and packaging tests green.
3. Build and sign a separate candidate, preserving earlier candidates.
4. On the current Mac, open the popover from the clicked Needlbar status item and visually verify
   that the popover body begins below the menu-bar boundary and remains anchored to that icon.
5. Reconfirm outside-click dismissal. The actual macOS 14 arm64 acceptance gate remains separate.

## Non-Goals

- Redesigning popover content, size, glass appearance, or animation.
- Replacing `NSPopover` with `NSPanel`.
- Changing notification, widget, provider, authentication, or export behavior.
- Committing a release, pushing, tagging, notarizing, or publishing an artifact.
