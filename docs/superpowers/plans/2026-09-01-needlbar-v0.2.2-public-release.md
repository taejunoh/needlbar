# Needlbar v0.2.2 Public Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Needlbar `v0.2.2` exactly once from a later, green `main` commit, with the signed/notarized arm64 ZIP and a SHA-256 sidecar verified after public download.

**Architecture:** Keep release-source truth in the host/widget plists, phase-aware README/STATUS pair, and release notes; make `scripts/notarize-app.sh` create the checksum only after it has validated the stapled final ZIP; have the tag-only workflow transport those two validated files unchanged from `validate` to `publish`. Existing documentation-shell tests select prepared versus public copy from the exact Public Release Record heading, then enforce version alignment, artifact boundaries, release notes, and workflow privilege boundaries. Human-authorized tag creation and post-publication verification remain outside automation.

**Tech Stack:** Bash, Ruby/YAML contract checks, GitHub Actions, Swift/AppKit package resources, Developer ID signing, Apple notarization, GitHub Releases.

**Spec:** `docs/superpowers/specs/2026-09-01-needlbar-v0.2.2-public-release-design.md`

## Global Constraints

- This plan changes release/version/documentation/automation only. Do not change providers, credentials, Cursor behavior, analytics data flow, exports, widgets, notifications, telemetry, Git/forge behavior, or the macOS 14 target.
- The host `Resources/Info.plist` and widget `WidgetExtension/NeedlbarWidgetExtension-Info.plist` must both be exactly `CFBundleShortVersionString=0.2.2` and `CFBundleVersion=2`.
- Preserve the local-package boundary, the exact Cursor privacy sentence, and the v0.2.1 macOS 14 Widget Gallery/App Group caveat. A local ad-hoc `make package` archive is never described as the public artifact.
- Preserve historical `docs/STATUS.md` tagless-RC and release-validation sections as historical evidence. Do not rewrite them to imply their old runs published this release.
- `workflow_dispatch` stays tagless validation. Only a `v*` tag push may reach `publish`; `publish` must only use the artifacts uploaded by its own successful `validate` job.
- Do not run `gh release create`, upload an asset manually, force-move/delete/recreate a tag, or delete/edit a GitHub Release to hide a failure.
- Never print certificate material, Apple ID, team/account identifiers, tokens, app-specific passwords, keychain paths, or private archive contents. Store transient signing material only under the existing private `umask 077` work directory.
- Pre-release evidence is historical only: signed tagless RC [33524771615](https://github.com/taejunoh/needlbar/actions/runs/33524771615) at `15c229f` and docs CI [33526409582](https://github.com/taejunoh/needlbar/actions/runs/33526409582). Select a new exact green `main` commit at release time.
