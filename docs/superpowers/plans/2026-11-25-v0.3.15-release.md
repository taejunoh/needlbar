# Needlbar v0.3.15 Release Implementation Plan

> **For agentic workers:** the root session coordinates the release; the user approves the
> protected `release` environment, every merge to `main`, and the on-screen checks. Steps use
> checkbox syntax. Every step marked **USER** waits for the user; the agent never does it for them.
> REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** Publish `main` as Needlbar v0.3.15 build 18 (everything merged since the v0.3.14 tag
`59be993`), with accurate upgrade notes, a notarized GitHub Release, the Homebrew Cask on 0.3.15,
the released build installed on the maintainer's Mac, and public records whose README contracts
pass. This plan is roadmap step 6 and covers steps 7 to 9 of
`docs/superpowers/plans/2026-11-25-v0.3.15-roadmap.md`.

**Architecture:** The established sequence of `2026-10-30-v0.3.14-release.md`, at one frozen
commit G: a docs-only preparation PR (notes, STATUS, HANDOFF), one protected tagless run at G, an
annotated tag at G whose push runs validate and publish, independent verification of the public
download, the Cask update, the canonical install with a rollback backup, and only then the
public-record PR that flips README availability and adds the v0315 public contract. Measured values
go into one evidence file and reach the documents only through `render.rb`, which refuses to write
while any value is missing.

**Tech Stack:** GitHub Actions `release.yml` (`macos-15`, Xcode 16.2 pin, protected `release`
environment), `gh` 2.105, `codesign`, `xcrun stapler`, `spctl`, `ditto`, `lsregister`,
`pluginkit`, `/usr/bin/log`, Homebrew Cask in `taejunoh/homebrew-tap`, Ruby 4 and Python 3 for the
tool files in Appendix A, `bash scripts/tests/notarize-app-tests.sh`.

## Global constraints

- **Version:** host and widget stay exactly `0.3.15` / `18`. They already carry these values
  (`Resources/Info.plist`, `WidgetExtension/NeedlbarWidgetExtension-Info.plist`), and
  `.github/workflows/release.yml` already has `body_path: docs/releases/v0.3.15.md`; the current
  `test_v0315_release_metadata_contract` enforces all three. **No build bump is needed:** build 18
  was never published (the 2026-11-02 candidate was not tagged; spec 2026-11-03 §11). Needlbar has
  no updater, Homebrew compares the version string, and tagless builds 18 were installed only on the
  maintainer's Mac. Consequence: the installed tagless build and the public build both report
  0.3.15 / 18, so Task 6 tells them apart by code directory hash, never by version.
- **Tag:** annotated `v0.3.15` with message `Needlbar v0.3.15`, at explicit G, pushed alone, never
  retargeted. Publishing happens only on a tag push: `publish` runs only when
  `github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')`. `gh workflow run
  release.yml` (any ref) is a tagless validation that never publishes.
- **Artifacts:** `Needlbar-macos-arm64.zip` and `Needlbar-macos-arm64.zip.sha256`; Actions artifact
  name `Needlbar-macos-arm64-notarized`; team `3BMF4LM6TM`; signing authority
  `Developer ID Application: Taejun Oh (3BMF4LM6TM)`; bundle IDs `com.taejunoh.needlbar` and
  `com.taejunoh.needlbar.widget`; minimum macOS `14.0`; arm64 only.
- **Runner:** `macos-15` with `/Applications/Xcode_16.2.app`. A different image or Xcode in the
  run log is a stop-and-ask condition.
- **Protected environment:** `release` has required reviewers and allows `main` and tags `v*`.
  **USER** approves each run in the GitHub web UI. Never approve through the API, change the
  environment, read secrets, or bypass Gatekeeper.
- **No `claude`, no credentials:** the agent never runs `claude` (smoke sets
  `NEEDLBAR_DISABLE_CLAUDE_USAGE_PROBE=1`), and never reads Keychain items,
  `~/.claude/.credentials.json`, `~/.claude.json` or `~/.codex/auth.json`. It reads only Needlbar's
  `QuotaRefreshDiagnostic` and `ClaudeQuotaFailureDiagnostic` log lines.
- **Stray copies hijack the widget (2026-11-24):** never leave a `Needlbar.app` outside
  `/Users/taejunoh/Developer/LFG/needlbar-runtime/latest/`. Do not run `make package` or
  `make smoke` unless `dist/` is unregistered with `"$LSREG" -u "$WT/dist/Needlbar.app"` and deleted
  right after. Every extracted bundle in this plan lives in a scratch directory and is unregistered
  and deleted in the same step. After each such step `pluginkit -m -A -D -v -i
  com.taejunoh.needlbar.widget` must list exactly one plug-in at
  `/Users/taejunoh/Developer/LFG/needlbar-runtime/latest/Needlbar.app/Contents/PlugIns/NeedlbarWidgetExtension.appex`.
- **Checkouts:** work in `/Users/taejunoh/Developer/LFG/needlbar-claude-handoff` on new branches
  from `origin/main`. Leave its untracked `.superpowers/brainstorm/` alone. Never touch the primary
  checkout `/Users/taejunoh/Developer/LFG/needlbar` (its `dist/` holds only an old ZIP).
- **Shell:** use `/usr/bin/log`, not `log` (zsh has a builtin of that name). Shell state does not
  persist between agent Bash calls: every command block below starts by sourcing `env.sh`. Wait for
  runs with `gh run watch` in the background, not with `sleep`.
- **Scope:** no product code changes, no redesign, no new provider work. Findings go to the roadmap
  backlog. Do not claim Anthropic's agreement, native macOS 14 acceptance, overnight or reset
  reliability, or that Codex reads no credentials.

# Usage: ruby render.rb EVIDENCE_ENV TEMPLATE OUTPUT
# EVIDENCE_ENV holds KEY=value lines; every @@KEY@@ in TEMPLATE must have a value.
env_path, template_path, output_path = ARGV
values = File.readlines(env_path, chomp: true).reject { |l| l.strip.empty? || l.start_with?('#') }
                .to_h { |l| l.split('=', 2) }
text = File.read(template_path).gsub(/@@([A-Z0-9_]+)@@/) do
  values.fetch(Regexp.last_match(1)) { abort "render: no value for #{Regexp.last_match(1)}" }
end
abort 'render: an @@ token remains' if text.include?('@@')
File.write(output_path, text)

### `weekday-summary.rb`

Task 0.3: summarises one day of Needlbar's refresh and failure log lines; exit 3 on a gate failure.

<!-- file: weekday-summary.rb -->
````ruby
# Usage: ruby weekday-summary.rb LOG.ndjson
# Reads only Needlbar's QuotaRefreshDiagnostic and ClaudeQuotaFailureDiagnostic lines.
require 'json'
require 'time'
allowed = %w[startup manual windowReset backoffRetry periodic automaticResumed]
runs = []
failures = Hash.new(0)
early_timeouts = 0
File.foreach(ARGV.fetch(0)) do |line|
  next unless line.start_with?('{')
  event = JSON.parse(line) rescue next
  message = event['eventMessage'].to_s
  if message.start_with?('quotaRefresh ') && message.include?(' phase=completed ') && message.include?(' durationMs=')
    runs << message.split(' ').drop(1).map { |pair| pair.split('=', 2) }.to_h
  elsif message.start_with?('claudeQuotaFailure ')
    origin = message[/origin=(\S+)/, 1]
    failures[origin] += 1
    duration = message[/durationMs=(\d+)/, 1]
    early_timeouts += 1 if origin == 'usageProbeTimedOut' && duration && duration.to_i < 60_000
  end
end
abort 'no completed /usage runs in this log' if runs.empty?
durations = runs.map { |run| run.fetch('durationMs').to_i }.sort
starts = runs.map { |run| [Time.iso8601(run.fetch('start')), run.fetch('trigger')] }.sort_by(&:first)
periodic_gaps = starts.each_cons(2).select { |(_, (_, trigger))| trigger == 'periodic' }.map { |(a, _), (b, _)| (b - a).round }
unexpected = (runs.map { |run| run['trigger'] }.uniq - allowed).sort
puts "WD_RUNS=#{runs.size}"
puts "WD_FIRST=#{starts.first.first.utc.iso8601}"
puts "WD_LAST=#{starts.last.first.utc.iso8601}"
list = ->(tally) { tally.empty? ? 'none' : tally.sort.map { |key, count| "#{key} #{count}" }.join(', ') }
puts "WD_TRIGGERS=#{list.(runs.map { |run| run['trigger'] }.tally)}"
puts "WD_OUTCOMES=#{list.(runs.map { |run| run['outcome'] }.tally)}"
puts "WD_MEDIAN_MS=#{durations[durations.size / 2]}"
puts "WD_MAX_MS=#{durations.last}"
puts "WD_MIN_GAP_S=#{periodic_gaps.min || 'none'}"
puts "WD_FAILURES=#{list.(failures)}"
warn "GATE: unexpected triggers #{unexpected}" unless unexpected.empty?
warn "GATE: a periodic start came #{periodic_gaps.min} s after the previous start" if periodic_gaps.any? { |gap| gap < 900 }
warn "GATE: #{early_timeouts} timeout(s) under 60 s" if early_timeouts.positive?
exit((unexpected.empty? && periodic_gaps.none? { |gap| gap < 900 } && early_timeouts.zero?) ? 0 : 3)
````

You can also turn them on in Settings with **Check Claude quota automatically**, or with **Turn on** in the dashboard's Claude row. While they are off, Needlbar runs `claude` only when you choose **Check now**, so after a launch the Claude quota can stay empty until you do, unless the Claude Code status line has reported it, and Claude quota alerts come only from the readings you start.
- Codex is unchanged: Needlbar still reads `~/.codex/auth.json` (or `$CODEX_HOME/auth.json`) for the Codex quota request, which goes directly to the provider. Cursor is unchanged.

Claude quota:

- Needlbar runs `/usage` through your installed Claude Code and reads its usage report. The command is fixed and runs without a shell, in one fixed folder in the temporary directory that is emptied before each run, for at most 60 seconds, and Needlbar ends the process group it started afterwards. A process that moved to its own session or group is not covered. Its output is not logged or stored. Needlbar never runs `claude auth` or opens a login flow.
- With automatic checks on, runs also happen when Needlbar starts, when you turn them on or show Claude again, when a displayed window's reset passes, and after 15 minutes without a run, and they pause while Claude is hidden from both the menu bar and the dashboard. Automatic runs are in practice 15 minutes apart, and at least 5 minutes apart after a reset or a failed run. A change in Claude Code's local usage records does not start a run, because each run makes Claude Code scan its session transcripts from the last 7 days. Opening the dashboard does not start one. After repeated failures Needlbar waits 5, 10, 20, then 30 minutes.
- When `/usage` finishes without plan usage, which Claude Code does when it is signed out or not using a Claude plan, Needlbar shows **Claude Code didn't report plan usage** and suggests running `claude auth login` in Terminal, then **Check now**. It does not retry that state on its own; the next automatic run or **Check now** tries again. When Claude Code reports no usage for another reason, Needlbar says it could not check Claude Code and, if that continues, suggests running `claude` in Terminal to check its sign-in; with automatic checks on, it retries after a wait.
- A window the report leaves out is hidden, never shown as zero. On accounts without a five-hour window, the quota shows the weekly windows.
- The Claude Code status line stays as the second source and last-known values as the third, labelled with the time they were checked. A newer valid reading wins whichever source it came from.

Overview widget:

- Claude and Codex each have a column with the remaining percent, a bar, and one line with the reset countdown, **Last checked** when the reading is old, or **Quota unavailable**. A footer shows today's tokens and estimated cost. The title row, the Fresh/Stale and Partial/Complete words, the Cursor row and the Today updated line are gone.

Anthropic's terms: how running your installed Claude Code relates to them is described in the README section "Claude Code and Anthropic's terms". A run takes longer as the session transcripts from the last 7 days grow: on one Mac the median run took about 8 seconds, and an earlier run used about 5 seconds of CPU and 454 MB of peak memory. A reading shows as last known after a failed run or once it is 20 minutes old. The usage report is marked experimental and can change, in which case Needlbar shows last-known values. Only the three install paths above are searched. Fable matching depends on a display label. Claude Code may renew its own login during a run, and `claude` itself may show a Keychain prompt.
