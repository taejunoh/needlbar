# Needlbar v0.2.1 Menu Panel Placement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the native popover shell with an interactive menu panel whose entire visible frame is centered below the clicked status item and never crosses that display's menu-bar boundary.

**Architecture:** Keep the existing Overview/provider SwiftUI views and `MenuBarController` content selection. Introduce a pure placement unit, an AppKit `NSPanel` presenter, and status-item screen anchors; then migrate the controller from `NSPopoverDelegate` to the presenter callback while retaining generation-guarded outside-click cleanup.

**Tech Stack:** Swift 6, AppKit `NSPanel`/`NSStatusItem`/`NSVisualEffectView`, SwiftUI hosting, Swift Testing, existing SwiftPM/Rust package pipeline, Developer ID local signing.

**Spec:** `docs/superpowers/specs/2026-08-31-needlbar-v0.2.1-popover-anchor-fix-design.md`

## Global Constraints

- Preserve macOS 14 as the minimum deployment target and Apple Silicon as the current packaging target.
- Preserve existing Overview/provider content, provider data flow, authentication, notifications, widgets, and exports.
- Resolve anchors from the clicked status button's own window and screen; never use `NSScreen.main`.
- Install outside-click monitoring only after a successful presentation and guard stale callbacks.
- Do not push, tag, notarize, publish, or mutate the Apple developer portal.

- [ ] **Step 3: Implement the minimal presenter**

Define:

```swift
@MainActor
protocol MenuPanelPresenting: AnyObject {
    var isShown: Bool { get }
    var onDismiss: (@MainActor () -> Void)? { get set }
    @discardableResult
    func present(_ contentViewController: NSViewController,
                 anchoredAt anchor: StatusItemPresentationAnchor) -> Bool
    func dismiss()
}
```

Use these narrow AppKit seams so tests observe presenter behavior rather than framework internals:

```swift
@MainActor
protocol MenuPanelWindowing: AnyObject {
    var frame: NSRect { get }
    var contentViewController: NSViewController? { get set }
    func setFrame(_ frame: NSRect, display: Bool)
    func orderFrontRegardless()
    func orderOut(_ sender: Any?)
}

@MainActor
protocol MenuPanelDismissalMonitoringToken: AnyObject {
    func cancel()
}

@MainActor
protocol MenuPanelDismissalMonitoring: AnyObject {
    func start(
        panelFrame: @escaping @MainActor () -> NSRect,
        dismiss: @escaping @MainActor () -> Void
    ) -> any MenuPanelDismissalMonitoringToken
}
```

`AppKitMenuPanelPresenter` owns one borderless `.nonactivatingPanel` subclass. Configure it with
`.popUpMenu` level, `[.transient, .moveToActiveSpace, .fullScreenAuxiliary]`, clear background,
`isOpaque = false`, `hasShadow = false`, and `becomesKeyOnlyIfNeeded = true`; override
`canBecomeKey` as true and route `cancelOperation` to a stored dismissal closure. Extend the panel
to conform to `MenuPanelWindowing`.

Wrap the supplied hosting controller in an `NSVisualEffectView(material: .popover)` with active
state, 18-point corner radius, clipped bounds, and a one-point separator-colored border. Measure
the hosted view's `fittingSize` after layout, require a valid placement frame, apply it, and show
without activating the application. `AppKitMenuPanelDismissalMonitor` implements the monitoring
protocol with one `NSEvent.addLocalMonitorForEvents` call and one
`NSApplication.didResignActiveNotification` observer. It classifies mouse-down using
`NSEvent.mouseLocation` and the current panel frame, passes ordinary events through, consumes only
Escape, and calls `dismiss` for outside clicks, Escape, or deactivation. Its token removes both
registrations exactly once. The presenter owns the token and also cancels it during idempotent
`dismiss()` and deinitialization.

- clicking a different module reanchors the existing presenter;
- internal `performSettingsAction()` and Claude/Codex/Cursor external actions dismiss before

- internal `performRetryAction()` leaves the panel shown;

- [ ] **Step 3: Implement the controller migration**

Remove `NSPopoverDelegate`, the `NSPopover` dependency, `popoverDidClose`, and all direct
`performClose` calls. Inject `MenuPanelPresenting = AppKitMenuPanelPresenter()`. Set `onDismiss`
once during initialization to call a controller cleanup method that increments the presentation
generation, cancels the global monitor, clears the active module, and removes a temporary deep-link
item once.

Before an async snapshot fetch, increment a request generation. If the same module is already
shown, dismiss and return. Ignore a completed fetch whose generation is no longer current. Build
the unchanged SwiftUI view in an `NSHostingController`, resolve the clicked status item's anchor,
and call `present`. Only on success record the module and start a generation-guarded global monitor.
On anchor/presentation failure, run the same cleanup path so deep-link items cannot leak.

Settings and provider-authentication closures call `panelPresenter.dismiss()` before the existing
action. Retry retains the current behavior. `stopObserving()` dismisses first and remains
idempotent if the presenter callback also cancels monitoring.
