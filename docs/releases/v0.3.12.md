Needlbar v0.3.12 stops presenting Claude Code status-line quota values that were received more than 24 hours ago.

- A five-hour or seven-day value reported by the Claude Code status line and received more than 24 hours ago is now treated as no value, not as **Last known**. Each window ages from its own local receipt time; a value received exactly 24 hours ago is still shown as last known.
- When the direct Claude quota update is also failing because the Claude Code access on this Mac has expired, the Claude popover, Settings, and dashboard show **Quota unavailable** with the existing **Claude Code access on this Mac expired** explanation, instead of a **Last known quota** received weeks earlier. The **Reported by Claude Code** and **Received locally** lines are not shown for such a value.
- The menu bar Claude value shows **—** instead of the old status-line value.
- Direct Claude quota values, status-line values received within the last 24 hours, the widget, JSON export, and quota alerts are unchanged. The saved status-line data is not deleted or rewritten, and a newer status-line report is shown again as before.

Direct last-known values are kept only in memory, so they are lost when Needlbar restarts. Credential renewal is not implemented: Needlbar does not renew Claude Code access. The status-line bridge receives values only from interactive terminal Claude Code sessions, so it does not help while Claude Code runs from the Claude desktop app. Menu bar titles update at the next published snapshot, normally within 5 minutes. Native overnight, quota-reset, sustained unattended, and native macOS 14 acceptance remain unverified.
