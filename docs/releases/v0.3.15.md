Needlbar v0.3.15 adds an in-app way to give the macOS Keychain confirmation that the direct Claude quota update can need. v0.3.14 had no in-app way to give it, so the Claude quota stayed on **Credential access unavailable** until access was restored outside the app. This release fixes that.

- While the Claude quota shows **Credential access unavailable**, an **Allow Keychain access** button now appears in the dashboard and in Settings under Connection, beside **View Claude usage**. One click asks macOS once for the `Claude Code-credentials` item, and macOS may show its Keychain dialog. If you allow it, the Claude quota appears. If you cancel or deny, nothing changes: the same state and button stay, and Needlbar does not ask again by itself.
- Needlbar only asks when you click. Timers, startup, waking the Mac and background updates still show no Keychain dialog.
- A Keychain dialog left open no longer stops Codex and Cursor quota updates. They keep updating while it waits for your answer.
- A line beside the button suggests choosing Always Allow in the dialog. Whether macOS keeps that access for later background updates depends on macOS. If it does not, **Credential access unavailable** can return at a later background update, and so can the button.

Credential renewal is not implemented: Needlbar does not renew Claude Code access, so the Claude quota still shows **Claude Code access on this Mac expired** until Claude Code runs in Terminal, and that state has no button. Direct last-known values are kept only in memory, so they are lost when Needlbar restarts. The status-line bridge receives values only from interactive terminal Claude Code sessions. Native overnight, quota-reset, sustained unattended, and native macOS 14 acceptance remain unverified. The new button has not been tried against a real macOS Keychain dialog.
