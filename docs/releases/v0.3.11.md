Needlbar v0.3.11 explains an expired Claude Code access instead of a generic quota failure and fixes how the status-line helper restores signal handling.

- When a direct Claude quota update fails because the access the Claude Code command-line tool saved on this Mac has expired, the Claude popover, Settings, and dashboard show **Claude Code access on this Mac expired** instead of **Quota access unavailable**. Other quota failures keep their existing reasons.
- In the popover and Settings, a detail line explains that Needlbar reads the access the Claude Code command-line tool saves on this Mac, that the Claude desktop app does not renew this access, and that it updates after Claude Code runs in Terminal. The text states facts; it is not an instruction.
- When the five-hour and seven-day windows are still recent through the Claude Code status line, they are shown as before and the explanation appears once, on the Fable line. The menu bar, widget, JSON export, and notifications are unchanged.
- The Claude Code status-line helper now saves and restores complete interrupt, terminate, and hang-up signal dispositions, so an ignored signal or a caught handler's mask and flags are restored exactly. The shipped helper runs one command per process, so its observable behavior is unchanged.
- Test reliability only: a lost wakeup that could stall the refresh coordinator tests in CI is fixed; refresh and usage-file-watcher test waits use explicit readiness signals and end on cancellation under a time limit; blocking test fakes cap each hold at 30 seconds; and in-process status-line runner tests run one at a time.

Credential renewal is not implemented: Needlbar does not renew Claude Code access, and the explanation adds no button, link, sign-in, or other new action. The status-line bridge receives values only from interactive terminal Claude Code sessions, so it does not help while Claude Code runs from the Claude desktop app. Signals the helper does not forward (SIGKILL, SIGQUIT, SIGUSR1/SIGUSR2, and signals sent to the whole process group) can still leave the original command running. Cancellation of blocked synchronous calls is not implemented. Native overnight, quota-reset, sustained unattended, and native macOS 14 acceptance remain unverified.
