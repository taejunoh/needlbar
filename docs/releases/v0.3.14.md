Needlbar v0.3.14 fixes two ways the direct Claude quota update could stop working on a Mac where Claude Code saves its access in the login keychain.

- When more than one `Claude Code-credentials` item exists in the Keychain, Needlbar now reads the one saved under your macOS login name, which is the one the Claude Code command-line tool uses. Before, any second item with the same name (for example one with the account `unknown`) made every Claude quota update fail. If no item is saved under your login name, Needlbar still reads the only matching item, and it still fails safely instead of guessing when it cannot tell which item to use.
- Background quota updates no longer show a macOS Keychain access dialog. While the dialog waited for an answer, Claude, Codex and Cursor quota updates all stopped. When reading the Claude Code access would need your confirmation, the Claude quota now shows **Credential access unavailable**, and **Sign in with Claude** asks for that confirmation as before.
- Messages, the popover, Settings, dashboard, menu bar, widget, JSON export, quota alerts and network requests are otherwise unchanged.

Credential renewal is not implemented: Needlbar does not renew Claude Code access, so the Claude quota still shows **Claude Code access on this Mac expired** until Claude Code runs in Terminal. Direct last-known values are kept only in memory, so they are lost when Needlbar restarts. The status-line bridge receives values only from interactive terminal Claude Code sessions. Native overnight, quota-reset, sustained unattended, and native macOS 14 acceptance remain unverified.
