Needlbar v0.3.13 records more precise local diagnostics when a direct Claude quota update fails. Nothing in the app looks or behaves differently.

- The local Claude quota failure log entry now also names the error code of the failed attempt, from a closed list (for example `providerUnavailable` or `schemaChanged`).
- Failures that were all logged as `otherFailure` are now split into closed origins: an ambiguous Keychain match (`credentialStoreAmbiguous`), a saved Claude Code credential in a format Needlbar does not recognize (`credentialFormatUnrecognized`), an HTTP 5xx answer from the usage endpoint (`usageEndpointServerError`), and a usage response Needlbar does not recognize (`usageResponseUnrecognized`). Other failures stay `otherFailure`.
- The entry stays in the macOS unified log on this Mac (subsystem `com.taejunoh.needlbar`, category `ClaudeQuotaFailureDiagnostic`). No message, URL, header, response body, token, path or HTTP status is logged, and nothing is sent anywhere.
- Error messages, the Claude popover, Settings, dashboard, menu bar, widget, JSON export, quota alerts, credential precedence, network requests and the C interface are unchanged.

Credential renewal is not implemented: Needlbar does not renew Claude Code access. Direct last-known values are kept only in memory, so they are lost when Needlbar restarts. The status-line bridge receives values only from interactive terminal Claude Code sessions. Native overnight, quota-reset, sustained unattended, and native macOS 14 acceptance remain unverified.
